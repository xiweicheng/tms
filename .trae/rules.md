# TMS 项目 Trae 规则配置

## 1. 项目概览

TMS(Teamwork Management System)是基于频道模式的团队沟通协作+轻量级任务看板，支持mardown、富文本、在线表格和思维导图的团队博文wiki，i18n国际化翻译管理的响应式web开源团队协作系统。

技术栈：
- 后端：Java 1.8, Spring Boot 1.5.14
- 前端：JavaScript, Vue.js
- 数据库：MySQL, PostgreSQL
- 构建工具：Maven

## 2. 代码风格规范

### 2.1 Java 代码风格

#### 命名规范
- 类名：使用驼峰命名法，首字母大写（如：`UserService`）
- 方法名：使用驼峰命名法，首字母小写（如：`getUserById`）
- 变量名：使用驼峰命名法，首字母小写（如：`userName`）
- 常量名：使用全大写，单词间用下划线分隔（如：`MAX_RETRY_COUNT`）
- 包名：使用小写字母，单词间用点分隔（如：`com.lhjz.portal.util`）

#### 代码结构
- 缩进：统一使用4个空格
- 大括号：独行放置，保持清晰层次
- 方法长度：单一职责，避免过长
- 代码组织：逻辑相关的代码放在一起，使用空行分隔不同逻辑块

#### 注释规范
- 文件头：包含版权声明、作者、功能描述和修改记录
- 公共成员：类、方法、接口必须添加Javadoc注释
- 复杂逻辑：添加详细的行内注释
- 注释风格：使用`/** */`进行文档注释，`//`进行行内注释

### 2.2 前端代码风格

#### 命名规范
- 组件名：使用大驼峰命名法（如：`UserComponent`）
- 变量名：使用小驼峰命名法（如：`userName`）
- 常量名：使用全大写，单词间用下划线分隔（如：`MAX_RETRY_COUNT`）
- 方法名：使用小驼峰命名法（如：`getUserInfo`）

#### 代码结构
- 缩进：统一使用2个空格
- 大括号：与语句同一行，保持代码紧凑
- 代码组织：按功能模块组织代码，使用空行分隔不同逻辑块

#### 注释规范
- 组件注释：添加组件功能描述和使用方法
- 复杂逻辑：添加详细的行内注释
- 注释风格：使用`//`进行单行注释，`/* */`进行多行注释

## 3. 开发流程规范

### 3.1 分支管理
- 主分支：`master`（稳定版本）
- 开发分支：`develop`（开发版本）
- 特性分支：`feature/xxx`（新功能开发）
- 修复分支：`fix/xxx`（bug修复）

### 3.2 提交规范
- 提交信息：使用语义化提交信息，格式为：`type(scope): subject`
  - type：feat（新功能）、fix（修复）、docs（文档）、style（格式）、refactor（重构）、test（测试）、chore（构建）
  - scope：修改的模块或文件
  - subject：简短描述修改内容
- 提交频率：保持原子提交，每个提交只包含一个功能或修复

### 3.3 代码审查
- 代码提交前：自查代码风格和功能正确性
- 代码合并前：进行代码审查，确保代码质量

## 11. 版本管理

### 11.1 版本号规范
- 版本号格式：`major.minor.patch`
  - major：重大变更，不兼容的API变更
  - minor：新功能，向后兼容
  - patch：bug修复，向后兼容

### 11.2 发布流程
- 开发完成：在develop分支进行开发
- 测试通过：合并到master分支
- 版本发布：打标签，发布版本
